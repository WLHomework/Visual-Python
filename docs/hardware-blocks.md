# 硬件积木与驱动清单（2026-10-22）

本文是 H7 收尾的硬件侧清单：支持矩阵、分类规模、驱动、验证状态与已知限制。它描述的是当前工作区实现，不是真机验收报告；真机结论见文末。

## 1. 支持矩阵

| 项目 | ESP32-S3 | ESP32-WROOM | ESP8266-ESP12E |
| --- | ---: | ---: | ---: |
| 工具箱条目（含 Python 积木） | 154 | 95 | 87 |
| 硬件专属积木 | 112 | 53 | 47 |
| P0 通用包（H6 下放） | 是 | 是 | 是 |
| H5 驱动包（DS18B20 / BMP280 / SHT30 / MPU6050 / TM1637 / 步进电机 / OLED 图形） | 是 | 否 | 否 |
| P2 扩展包（DS3231 / VL53L0X / OLED 进度条 / HTTP 下载/状态码 / MQTT 状态 / 红外 / 文件大小 / RFID / SD / 网页服务器 / 定时器 / BLE GATT） | 是 | 否 | 否 |
| 真机状态 | M3/M5 已由用户通过 | H6.4 未执行（无硬件，例外关闭） | H6.4 最小项通过（LED/ADC/PWM/I2C 扫描；LCD/BH1750 未接线） |

S3 的分类分布：输入/输出 6、控制 7、数学 1、串口 5、通信 18、网络 24、存储 11、传感器 16、执行器 5、灯光 6、显示 13（合计 112 个硬件专属条目）。WROOM 为 17 个分类 / 53 个硬件条目，ESP8266 为 17 / 47；两者的 Python 侧分类与 S3 相同（ESP8266 数学分类没有随机数积木）。

## 4. 已知限制

1. **S3 已超过 150 条自定上限**（154 条）。继续加积木前应先折叠分类或做“高级/兼容”分组，否则工具箱滚动和搜索质量会下降。
2. **P1/P2 仍只进 S3**。WROOM/ESP8266 目前只有 P0 通用包；H5 驱动包与 P2 扩展包没有下放。
3. **WROOM/ESP8266 未真机验证**。H6.4 只准备了脚本与接线表（`docs/hardware/README.md`），不能把 S3 的 M3/M5 结果当成另外两块板卡的结论。
4. **ESP8266 资源紧张**：A0 只有 0–1023、PWM 上限 1 kHz、Flash/RAM 小；一次只上传一个较大驱动，避免同时加载 LCD1602/BH1750 之外的多个纯 Python 驱动。
5. **I2C 共用总线**：OLED、LCD1602、BH1750、BMP280、SHT30、MPU6050、DS3231、VL53L0X 共用 `_i2c`；关闭总线后已缓存的对象需要重新初始化。
6. **定时器回调运行在中断上下文**：只允许简单的引脚/变量操作；不要放延时、打印、Wi-Fi 或长循环。最多 4 个定时器。
7. **网页服务器是阻塞式单请求**：`accept()` 会阻塞到有请求；必须放在“永远重复”里，且端口被占用或未连 Wi-Fi 时返回空串。
8. **红外只支持 NEC**：extended NEC 会被反码校验拒绝；等待期间阻塞，超时由积木参数控制。
9. **SD 卡固定 slot 2 / 20 MHz**：与 SPI 积木共用 GPIO 时注意冲突；热插拔和 5 V 电平都不安全。
10. **BLE GATT 只注册一组服务**：重复运行会重新注册；通知只在已连接时成功。
11. **DS18B20 每次读取等待 750 ms**；VL53L0X、DS3231、RC522、TM1637 的时序均为静态实现，需按 H6.4/M5 复核。
12. **OLED 图形按 128×64 设计**：其他尺寸下坐标与进度条需要自行调整。
